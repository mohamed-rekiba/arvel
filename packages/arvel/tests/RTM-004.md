## Gap log (escalations the Developer should know about)

1. **`with_routing(console=)` semantics**: The PRD says console paths are stored on the application but not loaded in WI-004. The current builder stores them in `_routing_paths`; the Developer needs to expose a getter on `Application` (e.g., `application.console_routes_path`) so WI-005 can pick them up. This is implicit in FR-004-009 acceptance criteria; flag for explicit ADR follow-up in Stage 3b.
2. **`arvel.config.lookup(key)` is a NEW function**: PRD says "the existing arvel.config accessor"; the existing accessor is class-based (`Config.of(cls)`), not key-based. QA-Pre introduced `arvel.config.lookup(key)` as a NEW public function under the same package. SA confirmation at Stage 4 needed; if SA prefers another spelling, this is a low-cost rename.
3. **Skeleton package data layout (`*.tmpl` vs `_dot_*`)**: ADR-121 defines the file-rename conventions but doesn't prescribe whether to use one, the other, or both. Skeleton tests accept either form (parametrized tuples). Developer chooses; document the choice in Stage 3b.
4. **Threat-model gap on user-controlled CLI flags**: SAD STRIDE-light covered the project name but not `--python` or `--no-install`. These are low-risk (`--python` is a string written verbatim into a TOML file; `--no-install` is a boolean), but Stage 4b should confirm.
